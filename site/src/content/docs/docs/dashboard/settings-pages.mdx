---
title: "Settings pages"
description: "7 grouped settings pages — Application, Email, Auth & security, Database, Automation, Integrations, Logs — each a tabbed page."
---

The Settings sidebar has 7 entries. Each is one page with tabs (the tab
lives in the URL, e.g. `/_/#/settings/email?tab=templates`, so a tab is
bookmarkable and shareable) rather than its own sidebar row — a page or
two per topic used to each get a row of its own, which grew past what a
sidebar should hold.

- **Application** — **General** (name, public URL, sender identity),
  **Branding** (logo, brand color, accent color), **Modules** (the batch
  API, and the Teams/Queue/ZIP export toggles — Teams applies
  immediately, Queue and ZIP export need a restart), **Storage**
  (S3-compatible file storage, plus its own **Storage limits** section —
  the image-transforms toggle/max dimension and the per-user storage
  quota, see [Files](/docs/concepts/files/#storage-quota)). Storage isn't
  an email concern, so it lives here rather than under Email → Delivery.
- **Email** — **Delivery** (SMTP or the zero-config `Log` backend),
  **Templates** (the visual/HTML editor, opened as its own full page from
  this tab), **Triggers** (`_emailTriggers`), **Mail log** (`_mailLog`,
  every send attempt), and **Dev inbox** — only shown while no real
  transport is configured (`smtp.enabled: false`); it lists every email
  the `Log` backend has "sent," newest first, with a detail pane
  rendering the HTML body in a sandboxed iframe alongside a plain-text
  view.
- **Auth & security** — **Superusers**, **Sessions** (`_sessions`, every
  live bearer/cookie token across every auth collection), **API keys**,
  **Network** (rate limits with a collection-name autocomplete, trusted
  proxy, superuser IP allow-list).
- **Database** — **SQL console**, **Extensions** (Postgres-only:
  PostGIS, pgvector, pg_trgm, ...), **RPC functions** (`_rpc`), **Backups**
  (including the cron schedule and how many scheduled backups to keep),
  **File manager**.
- **Automation** — **Cron jobs** (`_cron_jobs`), **Webhooks**
  (`_webhooks`), **Functions** (a read-only view of registered
  `pb_hooks` routes).
- **Integrations** — **Push** (`_push_subscriptions`), **LLM** (only
  shown once `llm.enabled` is on), **MCP**.
- **Logs** — **Request logs** (with an hourly-volume chart and retention/
  minimum-level/data-size settings), **Audit log** (`_audit_log`,
  append-only).

Every old direct link (`/settings/superusers`, `/settings/mail-log`, a
bookmarked `/settings/audit?action=...`, ...) still works — it redirects
to the new group and tab, filters and all.
