An executed, reproducible HTTP-level benchmark of a Cratebase release
build, run by one script (`benchmarks/run.sh`). The server is driven
by a plain-`fetch` Bun script — no SDKs — across six
categories (`create`, `auth`, `search`, `search-wide`, `search-auth`,
`delete`) at four concurrency levels (1, 20, 50, 100), median of 3 runs
after a discarded warm-up.

## Results

Latest idle-host run (2026-09-04), 16 vCPU / 27 GB shared sandbox, 0
errors. The standout: `search` at concurrency 50 reaches **49,986 req/s**
with p99 latency of 1.60ms; `create` at concurrency 100 reaches 11,960
req/s at p99 8.87ms.

**Read honestly:** the `auth` rows are bound by Argon2id password hashing
at OWASP parameters, not by request handling — they measure the cost of
the security parameters, not throughput work. This is a shared,
virtualized sandbox, not a dedicated benchmark rig — relative comparisons
within one run are more trustworthy than absolute numbers across runs.

Reproduce it yourself:

```sh
benchmarks/run.sh                       # builds, runs everything
benchmarks/run.sh --skip-build          # reuse target/release/cratebase
benchmarks/run.sh --concurrency=1,20    # any bench.ts flag is forwarded
```
