See [Email](/docs/email/overview/) for the template store, resolution
order, and SDK/JS-hook wrappers around these two endpoints.

### `POST /mails/send`

Superuser or [API key](/docs/concepts/authentication/api-keys/) only —
same `RequireSuperuser` gate as every other superuser endpoint, so an API
key (which always resolves to a superuser identity) works too.

```json
{
  "to": "user@example.com",
  "template": "welcome",
  "data": { "user": { "name": "Ada" } },
  "locale": "fr",
  "cc": ["ops@example.com"],
  "replyTo": "support@example.com"
}
```

`to`/`cc`/`bcc` each accept a bare address, `{ "address", "name" }`, or
an array of either. Either `template` (resolved through
[`_emailTemplates`](/docs/email/templates/)) or `subject` plus `html`/
`text` must be given — mixing both is fine (`template` wins). `to` +
`cc` + `bcc` together may not exceed 50 recipients (`400` past that, and
for any malformed address). Response:

```json
{ "id": "abc123", "status": "sent", "error": null }
```

`status` is `"sent"`, `"failed"` (with `error` set), or `"queued"` when
`settings.queue.enabled` — see [Sending → Delivery](/docs/email/sending/#delivery)
for the inline-vs-queued contract, and [Mail log](/docs/email/mail-log/)
for `id`'s corresponding `_mailLog` row.

### `POST /mails/preview`

Same body shape as `send` minus `to`/`cc`/`bcc`/`from`/`replyTo` (all
ignored if present) — renders without sending or logging anything.

```json
{ "subject": "Welcome to Acme!", "html": "<!DOCTYPE html>...", "text": "Hi Ada, ..." }
```
